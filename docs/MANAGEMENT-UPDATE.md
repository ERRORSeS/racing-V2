# Racing, medical care, market and performance update

This update implements the current requests on top of the V4/V5 work. It does not certify every cumulative PDF requirement.

## Playable changes

- **Race-level guide:** open Races → Race level guide. All eleven class definitions have actual conditions, suggested current-skill ranges, relevant workouts, examples and the next sensible step. Claiming/Handicap are parallel routes. Skill guidance is not an eligibility lock; inherited ceilings still apply. A Markdown copy is in `RACE-LEVEL-GUIDE.md`.
- **Selective news:** graded/Listed results, exceptional early performances or margins, five-win streaks, exceptional sales and famous-parent offspring. Routine wins, care, travel, ordinary births and monthly filler no longer flood the feed. Older routine stories remain saved but are hidden from the main feed. All headlines reference committed results/events.
- **Injuries:** twelve configured injury types with severity, context, prognosis and clinical recovery ranges. Training/race exposure occurs once per activity/day. A race injury can cause a genuine pulled-up outcome: no finish time, placing, prize or speed rating, but an official start remains. Race reports/replays retain the incident. No graphic visuals.
- **Player medical decisions:** stabilization is automatic, followed by Treat & reassess, Treat for comfort, Retire with aftercare or Retire as breeding prospect. Plans cost the displayed fee and retain ongoing records. Pending player cases do not silently clear or force retirement. Permanent restrictions cannot be bought away. New careers allow rare fatal complications; existing saved fatality preferences are retained. Death preserves identity, pedigree and career.
- **Per-horse automatic registration:** Races or Horse → Care. Each horse has its own switch, minimum race interval, maximum class and campaign goal. Entries use actual local location, readiness, official age, sex, wins/rating, qualifications, rest, jockey availability and funds. Training and auto entry remain separate. A confirmed entry is not silently scratched when its policy changes.
- **Classic pathway:** annually unique USA prep/Derby/Preakness/Belmont editions, 3YO entry, an evidence-backed season points table and a Derby points/rank gate. All three same-season wins are required for a Triple Crown. These use **fictional prep races and a disclosed synthetic-calendar/points approximation**, not a current official points feed. Edition venue/distance/rule overrides are supported. Other jurisdictions retain published class conditions; full international classic programs remain future work.
- **Monthly training:** base learning rate increases from 0.45 to 0.9, with Auto Balanced emphasizing sprint or distance work on selected working days. Rest, injury/starting gates, maturation and genetic caps remain. A last-30-day report sums actual skill changes and separately counts education/starting sessions. There is no unearned time-skip stat bonus.
- **Auction hierarchy:** Market → Auctions → Event → Category → Horse. Fourteen multi-tag category definitions, month/country rotation, new lot IDs, career-aware valuations, real NPC consignments, archived bid/outcome records and preserved horse identity. Category tabs can be empty when the world has no suitable stock. Nursing pairs cannot be split by an individual sale. Private Sales, My Bids and My Listings remain separate views. Advanced proxy bidding, premium schedules and contracts are not claimed here.
- **Pedigree careers:** previously unrecorded generated founder ancestors receive three shared, actually simulated historic fixtures with complete result links and earnings. These are explicitly labeled simulated founder history, never real-world imported history. Existing starts, current skills, cash and RNG are preserved. Missing founder history is generated in the worker on migration and when new founder ancestors appear; modeled founder backstories do not replace official track-record benchmarks. Normal prospect horses can still truthfully be unraced.

## Saving and speed

Normal player actions no longer display the full-screen processing overlay or wait for compression/IndexedDB writes. Actions keep rollback isolation while copying only owned/affected horses and mutable state. Immutable race archives are shared for ordinary edits. Background autosaves coalesce rapid clicks; the status shows pending/saving/saved or an error. Ordinary edits have a short pending window, so wait for Saved before closing the page; completed time skips are durably saved before returning control. Time skips flush earlier edits, run entirely in a persistent worker, and save the advanced state before another skip begins. New-career creation, save loading and imports also use the worker for heavy work.

Career summaries and official ratings are cached against immutable start arrays, and save validation indexes fixture/listing IDs instead of repeated scans. Static builds use a content-hashed module directory, including the worker, so cached scripts cannot mix releases. Save storage remains on the same origin/database/key.

A local Node benchmark on a generated ~12 MB career without seeded history measured full copies at 136–262 ms and targeted action snapshots at 6–15 ms (five samples). This measures transaction copying, **not browser end-to-end latency**. First-time creation or founder-history migration still requires simulation work; it runs off the UI thread and is persisted for later loads. Large multi-year skips still take time and are not represented as instantaneous.

## Compatibility and verification

Schema 6 accepts saves from schemas 1, 2, 3 and 5; migrations retain horse IDs, owner/breeder, genes/caps, records, balance and existing preferences. Nullable finish fields are only accepted for genuine pulled-up rows with zero prize; track records, awards, ratings and points exclude nonfinishers.

Tests cover class guidance, selective headlines, injury type distributions, care decisions, pulled-up persistence/rendering, fatal-case references, monthly gains/caps, per-horse entries, qualifying evidence/Triple Crown, catalog rotation/navigation, founder records, action rollback, serialized/coalesced saves, migration and hashed worker assets, alongside previous regressions.

Headless Chromium browser smoke testing passed against the built, versioned site at 1440px desktop and 390px mobile widths. It covered creation, the level guide, ordinary edits without the processing overlay, background save/reload, daily/monthly advancement, completed starting, automatic maiden registration, event/category browsing, placing an auction bid and a fixture-injected medical case treated and then retired with aftercare. No browser page errors were recorded. A tested ordinary Auto Training click updated in about 102 ms. This is a smoke test, not full cross-browser/accessibility certification. Full international series, advanced market contracts/proxy bidding and long-run PDF acceptance matrices remain open.
